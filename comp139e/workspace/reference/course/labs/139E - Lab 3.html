Modules, Testing, and Trigonometry

In the lectures, I have emphasized the importance of testing when developing reliable software. Quite often, developing tests is much more work than writing the code being tested. Luckily (for you), I have written the tests and you only need to write a few functions.

My code for testing your module is testTrigMain.cpp. Do NOT modify this file but be SURE that you understand what it is doing! I have not documented testTrigMain.cpp because you are required to figure it out.

Assignment

  1. This lab is a multi-file project (3 files), so you need to write a header file spherical.hpp that contains your function prototypes (and anything else that should go in that file...). Define 'M_PI' manually if it is not declared in NetBeans.

    #ifndef M_PI
        #define M_PI 3.14159265358979323846
    #endif

  2. Write a C++ module named spherical.cpp containing the implementation of the following functions: 
    
    // sphericalToRectangular returns the a unique, persistent array [x,y,z]
    double *sphericalToRectangular (double r, double azimuth, double inclination);

    // Returns a SphericalCoords struct ... be sure to declare one, put data in it, and return it!
    SphericalCoords rectangularToSpherical (double x, double y, double z);
    where the valid ranges for the spherical coordinates are:
    radius >= 0.0, -pi < azimuth <= pi, -pi < inclination <= pi,
    all angles are in radians (of course), and
    and we have defined 
    typedef struct {
    double radius;
    double azimuth;
    double inclination;
} SphericalCoords;
  3. You will need to find out how to convert to and from this particular 3-D coordinate system.
  4. Write an inline function to compute the radius (and you must be sure to use it!): 
        inline double getRadius (double x, double y, double z);
    (Remember that when an inline function is used in your program, the function call gets replaced by the code).
  5. Use default arguments so that all of your functions work with 2-D data. Some of the tests won't work if you forget to do this.
  6. When we have a known number of nameable data items to return, it is preferable to return a struct rather than an array.
    • One big advantage is that the fields of the struct are named, rather than having to remember array indices.
    • As you can see from this lab, the struct is best when we are returning a fixed number of items (3 in this case).
    • Arrays are OK if we are returning a large or variable number of items from the function but we must be careful with arrays!
    • In this lab, I want you to try both ways. Therefore, one function returns a struct and the other returns a pointer to an array.
    Remember that, to return an array from a function, that array cannot be a local variable in the function (and, of course, it cannot be a global variable or a file-scoped (static) variable)!
